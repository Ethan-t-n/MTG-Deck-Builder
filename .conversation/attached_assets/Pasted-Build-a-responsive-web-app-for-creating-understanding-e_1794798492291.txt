Build a responsive web app for creating, understanding, editing, and saving Magic: The Gathering decks. The app should work for beginners who want plain-English guidance and experienced players who want control over their decklist.

BUILD A DECK TWO WAYS

1. AI Deck Builder
- Let users type requests like “I want a black and blue Zombie Commander deck under $100.”
- Extract the format, colors, strategy, theme, budget, set preferences, and any exclusions from the request. Ask a short follow-up only when the answer would materially change the deck. Otherwise, build it and show any assumptions.
- Keep the assistant focused on Magic: The Gathering and deck building. For unrelated requests, respond with “I can help with Magic: The Gathering and deck building. What would you like to build or change?”
- Apply that scope on the server for every AI action, including deck chat and card explanations. Treat user text and imported deck content as data that cannot override app instructions.

2. Guided Builder
- Let users choose a format, number of colors, exact colors, playstyle, theme or no theme, and optional budget. Support colorless and every combination of Magic’s five colors. Keep the color count and color selections in sync.
- Offer playstyles such as aggro, control, combo, and midrange. Include “Help me choose” for users who are unfamiliar with a setting.
- Add optional preferences for playgroup competitiveness, a specific commander, cards to include or exclude, and whether infinite combos are welcome.
- Populate the searchable set picker from a real Magic card catalog. Include Universes Beyond sets and products when they appear in the catalog. Keep the list current through the catalog rather than hard-coding crossover names.
- Offer “Any legal set,” “Prefer selected sets,” and “Only selected sets.” For the strict option, use eligible printings from the selected sets. If the constraints prevent a complete legal deck, explain which setting is blocking the build and let the user change it.
- Send chat and guided requests through the same generation and validation pipeline.

USE REAL CARD DATA AND VALIDATE EVERY DECK

- Use Scryfall or an equivalent Magic card catalog for card identity, printings, images, official rules text, and available pricing. Use authoritative format rules for deck construction.
- Have the AI build from real catalog candidates. Resolve selections to catalog IDs, then validate the generated deck with code before displaying it as legal.
- Validate format-specific deck size, card legality, copy limits and exceptions, and sideboard rules where applicable. For Commander, validate commander eligibility, color identity, and the 100-card total including the commander.
- Recheck legality after every edit or import. Show what needs to be fixed if a deck is incomplete or illegal. Let users save it as a draft with that status visible.
- Show estimated pricing for the selected printings and identify cards with missing prices. If prices are missing, report the known subtotal and leave budget compliance unverified. If a deck exceeds the requested budget, show the difference and suggest cheaper swaps.

DECK RESULTS AND CARD DETAILS

- Display the commander where applicable, total card count, per-card quantities, legality status, and price estimate.
- Provide two views of the same decklist. List view shows quantities and card names. Image view shows card images with quantity labels. Preserve the selected view when the deck is reopened.
- In both views, clicking a card opens its image, official rules text, a plain-English explanation, and “Why it’s in this deck.” Explain how the card supports the deck’s plan and when to use it. Support cards with multiple faces.
- Include an AI deck guide covering the win plan, what to look for in an opening hand, early and late game priorities, key synergies, and how to recover if the plan is disrupted.
- Show the mana curve, mana sources by color, and role counts for ramp, draw, removal, and other relevant roles. Make each role clickable so users can see which cards were counted. A card can serve more than one role.

EDIT, CHAT, AND SAVE

- Allow manual additions, removals, and quantity changes. Let users lock cards they want to keep during AI-assisted revisions.
- Support requests like “Make this $30 cheaper” or “Add more Zombies.” Preview exact additions and removals, quantity changes, estimated cost impact, and legality before applying. Support undo for applied changes.
- Give each deck multiple persistent chat threads, such as “How to pilot it,” “Budget swaps,” and “Upgrades.” Let users create, rename, and reopen threads. Give each thread access to its own deck’s current list and settings. Keep chat history intact when the list changes.
- Chat can answer deck questions and propose edits. Apply proposed changes only when the user accepts them.
- Add a “Saved Decks” navigation item. Saving and reopening a deck should restore its decklist, settings, view preference, guide, and chat threads. Store deck data persistently and isolate each user’s saved decks.
- Support plain-text decklist import and export with card quantities. Flag unresolved names on import and let users correct them.

MILESTONES AND ACCEPTANCE TESTS

First milestone: ship the full build, validate, view, edit, save, and reopen loop. Start with Commander as the first fully supported format. Structure validation so other formats can be added independently. Only enable a format in the builder once its rules are implemented and tested.

Test with “Build a blue-black Zombie Commander deck under $100.” Verify it returns real cards and a legal 100-card list including the commander, handles missing price data honestly, opens card details in both views, and can be saved and reopened with two distinct chat threads. Verify an AI swap updates the list only after acceptance and can be undone. Also test an unrelated chat request and a strict set selection that cannot produce a full deck.

Second milestone: add a test-hand simulator. Let users draw seven from the actual deck, mulligan using the selected format’s rules, and draw through the first few turns. Add “Ask about this hand” so the AI can explain whether it would keep the hand and what it would try to play first. Add more formats as their validation is ready.

Keep AI credentials on the server in Replit Secrets. Provide clear loading and error states for generation and catalog requests. Start by implementing the first milestone, then run the acceptance tests and report what passed and what remains.
